# Data Management Engineering

Учебный проект по инжинирингу данных: загрузка и подготовка датасета, исследовательский анализ, работа с открытым API и запись данных в PostgreSQL.

## Датасет

В проекте используется набор экспериментальных данных, полученных при исследовании параметров внешнего дыхания лабораторных мышей методом неинвазивной плетизмографии всего тела (Whole-Body Plethysmography, WBP).

### Назначение датасета

Сформированный массив данных предназначен для исследования вариабельности параметров внешнего дыхания бодрствующих лабораторных мышей в состоянии покоя, статистического моделирования физиологических показателей и анализа взаимосвязей между ними.

Исходный экспериментальный протокол также предусматривает изучение индивидуальной вариабельности. Однако в предоставленной таблице отсутствуют идентификаторы животных, поэтому непосредственное разделение наблюдений по отдельным мышам невозможно без дополнительных метаданных.

### Характеристика выборки

Исследование проведено на интактной контрольной группе, состоящей из **8 клинически здоровых самцов лабораторных мышей аутбредной линии CD-1 в возрасте 3 месяцев**.

Выбор животных одного пола и возраста был направлен на снижение влияния гормональной и возрастной вариабельности на исследуемые дыхательные показатели.

### Протокол регистрации данных

Регистрация параметров внешнего дыхания осуществлялась методом неинвазивной плетизмографии всего тела (WBP).

Перед началом измерений проводилась обязательная **30-минутная акклиматизация** животных в измерительной камере, направленная на снижение влияния стресса от помещения в новую среду.

После адаптации выполнялась непрерывная регистрация дыхательной активности в течение **60 минут**.

### Формирование выборки

Поскольку измерения проводились на свободно передвигающихся бодрствующих животных, исходные записи могли содержать артефакты, связанные с двигательной активностью, грумингом и принюхиванием.

На этапе первичной обработки в пределах каждого одноминутного фрагмента вручную выделялись эпизоды стабильного спокойного дыхания без выраженных двигательных артефактов.

Для каждого отобранного эпизода специализированное программное обеспечение автоматически рассчитывало респираторные и технические показатели.

Итоговый датасет содержит **1000 наблюдений и 15 числовых признаков**. Каждая строка соответствует отдельному отобранному эпизоду дыхания, а столбцы содержат рассчитанные значения параметров.

### Описание признаков

**1. Временные показатели дыхательного цикла**

| Признак | Расшифровка | Описание |
|---|---|---|
| `Ti(s)` | Inspiratory Time | Продолжительность фазы вдоха, в секундах. |
| `Te(s)` | Expiratory Time | Продолжительность фазы выдоха, в секундах. При обструкции дыхательных путей может увеличиваться. |
| `EIP` | End-Inspiratory Pause | Пауза между окончанием вдоха и началом выдоха. В исходном описании указаны миллисекунды. |
| `EEp` | End-Expiratory Pause (EEP) | Пауза между окончанием выдоха и началом следующего вдоха. В исходном описании указаны миллисекунды. |
| `TR` | Relaxation Time | Время релаксации — время, за которое выдыхается определённая часть дыхательного объёма (65% согласно описанию исследования). |

**2. Объёмные и вентиляционные показатели**

| Признак | Расшифровка | Описание |
|---|---|---|
| `F` | Frequency | Частота дыхания — количество дыхательных циклов в минуту. |
| `vt` | Tidal Volume | Дыхательный объём — объём воздуха за один спокойный дыхательный цикл. |
| `mv` | Minute Volume | Минутный объём дыхания — общий объём воздуха, проходящий через лёгкие за одну минуту. |
| `AV` | Accumulated Volume | Накопленный объём — суммарный объём воздуха за период измерения согласно описанию исходного набора данных. |
| `volbal` | Volume Balance | Баланс объёмов — технический показатель разницы между объёмами вдоха и выдоха, используемый для контроля возможных утечек и артефактов. |

**3. Скоростные показатели воздушного потока**

| Признак | Расшифровка | Описание |
|---|---|---|
| `PIF` | Peak Inspiratory Flow | Максимальная скорость воздушного потока во время вдоха. |
| `PEF` | Peak Expiratory Flow | Максимальная скорость воздушного потока во время выдоха. |
| `EF50` | Expiratory Flow at 50% | Скорость воздушного потока при выдохе на уровне 50% дыхательного объёма. Может использоваться при анализе изменений проходимости дыхательных путей. |
| `Rpef` | Ratio of Time to PEF to Te | Отношение времени достижения пиковой скорости выдоха к общей продолжительности выдоха. Характеризует динамику выдыхательного потока. |

**4. Расчётные индексы дыхания**

| Признак | Расшифровка | Описание |
|---|---|---|
| `Penh` | Enhanced Pause | Безразмерный расчётный индекс, объединяющий временные и скоростные характеристики дыхательного сигнала. Используется как косвенный показатель изменений дыхательного паттерна, в том числе при исследовании бронхоконстрикции. Не является прямым измерением сопротивления дыхательных путей. |

## ETL-пайплайн

В рамках проекта разработан Python-пакет `etl`, автоматизирующий процесс получения, преобразования, проверки и сохранения экспериментальных данных.

Пакет расположен в директории `src/etl/` и реализует три основных этапа ETL:

1. **Extract (извлечение):** загрузка исходного CSV-файла из Google Sheets и чтение данных с помощью pandas.
2. **Transform (преобразование):** приведение признаков к числовым типам и проверка структуры датасета.
3. **Load (загрузка):** сохранение обработанных данных в Parquet и, при необходимости, запись выбранного количества строк в PostgreSQL.

### Структура ETL-пакета

| Модуль | Назначение |
|---|---|
| `__init__.py` | Инициализация Python-пакета |
| `extract.py` | Скачивание исходного CSV и загрузка данных в DataFrame |
| `transform.py` | Преобразование типов и проверка данных |
| `load.py` | Сохранение Parquet, получение реквизитов и запись в PostgreSQL |
| `main.py` | Последовательный запуск этапов ETL и обработка аргументов командной строки |

### Запуск ETL

Все команды выполняются из корневой директории проекта после установки зависимостей и пакета.

**Режим `prepare` — подготовка данных**

```bash
python -m etl.main --mode prepare
```

В этом режиме программа:

1. Скачивает исходный датасет в `data/dataset_for_DME.csv`.
2. Читает CSV и преобразует числовые признаки.
3. Проверяет наличие обязательных столбцов, числовые типы данных и отсутствие пустого датасета.
4. Сохраняет обработанные данные в `data/etl_processed.parquet`.

Подключение к PostgreSQL не выполняется. Режим подходит для проверки ETL без доступа к базе данных.

**Режим `replace` — загрузка в PostgreSQL**

```bash
python -m etl.main --mode replace
```

Программа выполняет все этапы подготовки данных, после чего подключается к PostgreSQL и записывает первые 100 строк в таблицу `giniyatullinadm` базы данных `homeworks`.

Для подключения используется локальный файл `data/creds.db`, содержащий реквизиты в таблице `access`.

**Важно:** режим `replace` удаляет существующую целевую таблицу и создаёт её заново. Перед запуском необходимо убедиться, что находящиеся в ней данные не требуется сохранять.

### Аргументы командной строки

| Аргумент | Назначение | Значение по умолчанию |
|---|---|---|
| `--mode` | Режим выполнения: `prepare` или `replace` | `prepare` |
| `--limit` | Количество строк для записи в PostgreSQL | `100` |
| `--help` | Отображение справки по аргументам | — |

Пример загрузки 50 строк:

```bash
python -m etl.main --mode replace --limit 50
```

Аргумент `--limit` должен быть положительным целым числом и не может превышать количество строк в датасете. Он применяется только в режиме `replace`.

### Проверка данных

Перед сохранением выполняется базовая проверка датасета:

- Таблица не должна быть пустой.
- Должны присутствовать все 15 обязательных признаков.
- Признаки должны иметь числовые типы данных.

Для преобразования типов используется `pandas.to_numeric()`. Значения, которые невозможно преобразовать в числа, переводятся в `NaN`. Проверка структуры и типов не является полной проверкой физиологической достоверности измерений. Выбросы и повторяющиеся строки автоматически не удаляются.

### Результат выполнения

При успешном выполнении ETL:

- Исходный CSV сохраняется в `data/dataset_for_DME.csv`.
- Обработанный датасет сохраняется в `data/etl_processed.parquet`.
- В режиме `replace` выбранное количество строк записывается в PostgreSQL.
- В консоль выводятся сообщения о прохождении основных этапов обработки.

Пакет можно запускать повторно с разными значениями аргументов без изменения исходного кода.

## Запись в PostgreSQL

Скрипт `scripts/write_to_db.py` переносит **первые 100 строк** из `data/dataset_for_DME.parquet` в PostgreSQL, в таблицу `giniyatullinadm` базы `homeworks`.

Этапы работы:

1. `load_dataset()` — читает Parquet и выбирает первые 100 строк.
2. `load_credentials()` — получает параметры подключения из локальной SQLite-базы `data/creds.db`, таблица `access`.
3. `connect_to_db()` — подключается к PostgreSQL через `psycopg2`.
4. `prepare_columns()` — преобразует имена столбцов для SQL и подбирает типы `DOUBLE PRECISION` или `TEXT`.
5. `write_dataframe()` — пересоздаёт таблицу, записывает строки через `executemany()` и подтверждает транзакцию (`commit`). При ошибке выполняется `rollback`.

**Подготовка:** сначала создайте Parquet командой `python data_loader.py` (если он отсутствует). Затем разместите `creds.db` в папке `data/`. Файл реквизитов базы данных не входит в репозиторий.

**Запуск:**

```bash
python scripts/write_to_db.py
```

При каждом запуске скрипт выполняет `DROP TABLE IF EXISTS` для таблицы `giniyatullinadm` и создаёт её заново. Не запускайте повторно, если содержимое существующей таблицы нужно сохранить.
